01 Problem

Judgments are long. Justice shouldn’t be hard to read.

Long, dense judgments

Pages of legal language, scattered across portals and formats.

Keyword search misses context

Similar facts and legal issues are hard to find.

English-only access

Citizens and regional-language users are left out.

Trust gap with AI

Summaries must be grounded, not hallucinated.

02 Solution

A multi-agent pipeline you can verify.

Six specialised agents, coordinated by an orchestrator. Every output links back to its source passage.

Agent 01

Ingest

PDF and OCR parsing, cleaning, chunking, embedding, indexing.

Agent 02

Extraction

Facts, issues, arguments, reasoning, statutes, precedents, verdict.

Agent 03

Summary

Expert and plain-language summaries, translated with IndicTrans2.

Agent 04

Retrieval

Semantic search by query or uploaded case, ranked by relevance.

Agent 05

Q&A

RAG answers with citations to the exact passages.

Agent 06

Guard

Checks every claim against source text and flags unsupported output.

03 Pipeline

From raw PDF to cited answer.

Phase 01

Ingest & Index

Collect SC/HC judgments and ILDC. PyMuPDF + Tesseract OCR. Chunk, embed, store in pgvector.

Phase 02

Understand

spaCy NER for statutes and sections. InLegalBERT section tagging. LLM summaries for experts and citizens.

Phase 03

Retrieve & Answer

Semantic search over embeddings. Citation-linked RAG Q&A. Optional outcome prediction.

Phase 04

Serve & Scale

FastAPI backend, Next.js web app, IndicTrans2 for regional languages, Dockerized.

ROUGEBERTScorePrecision@kRecall@kHallucination check
